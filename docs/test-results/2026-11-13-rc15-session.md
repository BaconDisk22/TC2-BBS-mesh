## Findings
1. **Network page says "Subscription requested (not yet confirmed)" for both brokers even while packets arrive** (SJMesh accepted 2). The label never updates after the subscription succeeds. Cosmetic, but misleading.
2. **Radio heard no messages in ~10 minutes** ("RX 0 / TX 0", "radio link unverified"). Likely a quiet mesh at 7 a.m.; the DM tests will confirm the radio path.
3. **Saved node list lags the screen:** MQTT sightings appear in the app before they're written to node-directory.db (they're flushed in batches). Expected, noted for anyone checking the file directly.
4. **An MQTT send can't show whether the broker took it.** rc.15 only marks "✓ on broker" when its own packet comes back, otherwise "? no confirmation" after 2 minutes. It doesn't record the broker's acknowledgement (PUBACK), so a dropped publish looks the same as one the broker accepted but didn't echo. CentralNJ text from others did arrive on the same subscription. Fixed after this session: a new "✓ broker accepted" status, and the Network label now confirms the subscription.
